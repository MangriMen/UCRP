## Ключевой вывод анализа

1. **Контракт и реализация расходятся системно.** OpenAPI описывает 90 операций;
   в `cmd/api/main.go` смонтировано 17. Расхождения не только в полноте, но и в
   формате: имена полей (`camelCase` в контракте против `snake_case` в DTO),
   пагинация (`page`/`page_size` против `limit`/`offset`), форма ошибок,
   структура ответов (`meta` отсутствует), коды ошибок.
2. **Сквозные сценарии US-1 → US-6 → US-5 сейчас нереализуемы через API.**
   Нет импорта, нет справочников, нет выгрузок, нет кампаний, нет лимитов
   контактов, нет аналитики. Воркер не обрабатывает задания
   (`jobTypes := []string{}`), то есть асинхронная цепочка не работает.
3. **Данные для тестов нельзя подготовить через API.** Нет `POST /tenants`,
   `POST /data-sources`, `POST /event-types`, `POST /users`. Единственный
   пользователь создаётся сидом из `UCRP_ADMIN_PASSWORD` с ролью `analyst`.
   Следовательно, E2E-тесты требуют прямой подготовки данных в БД.
4. **Ролевая модель не применяется.** `auth.RequireRole` реализован, но не
   подключён ни к одному маршруту: любой аутентифицированный пользователь
   получает доступ ко всем смонтированным операциям. Проверки 403 из
   US-8/US-10/US-11 и матрицы CRUD сейчас не проходят.
5. **Часть бизнес-правил нельзя проверить через API** (лимит контактов,
   контрольная группа, идемпотентность выгрузки, k = 5, match rate) — они
   зафиксированы в `04-e2e-plan.md` как ограничения тестирования.

## Что предлагается дальше

Тесты **реализованы и запущены** в `apps/api/e2e/` (Go `testing`, 88 тестов).
Результат прогона: **83 прошло, 1 упал, 4 пропущено** (режим `--report-only`);
зафиксировано **71 расхождение** контракта и реализации. Единственное падение —
реальный дефект продукта (поиск возвращает объединённые профили). Подробности —
в `06-final-report.md` и `07-test-gap-assessment.md`, артефакты — в `artifacts/`.
