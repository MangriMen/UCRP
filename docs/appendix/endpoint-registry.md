# Единый реестр эндпоинтов (источник истины для фаз C–E)

Базовый префикс всех путей: `/api/v1`. Формат: JSON, UTF-8, время в UTC (RFC 3339). Аутентификация: `Authorization: Bearer <JWT access>` (кроме `pub`). Единый формат ошибки: `{"error":{"code":"string","message":"string","details":[{"field":"string","reason":"string"}],"request_id":"string"}}`.
Коды: 400 валидация, 401 нет/просрочен токен, 403 нет прав, 404 не найдено, 409 конфликт состояния (лимит контактов, дубликат, занятый ресурс), 413 файл слишком большой, 422 семантически неверный файл, 429 лимит запросов, 504 таймаут `context`.

Роли: `R-1` Маркетолог УК, `R-2` Управляющий, `R-3` Арендатор, `R-4` Аналитик, `R-6` Система (воркеры; REST не используют — работают через очередь `job_queue`, см. раздел «Задания очереди»). `R-5` Гость доступа не имеет. `pub` — без токена, `any` — любая аутентифицированная роль.
Правило изоляции R-3: везде, где у R-3 стоит «own», `tenant_id` берётся только из JWT-claims (`tenant_id`); значение из пути/запроса сверяется с claim в `service`, несовпадение → 403; в `repository` все запросы получают обязательный `WHERE tenant_id = :claimTenant` (отдельные методы `...ForTenant`). R-3 не имеет доступа ни к одному эндпоинту, не отмеченному «R-3» в таблице.
