# 01. Резюме системы и допущения

## 1. Резюме

«Единая рекомендательная клиентская платформа для ТЦ» собирает данные арендаторов торгового центра (CRM/PMS, касса/POS, API, Excel/CSV) в единую модель событий и строит по ним единый профиль Гостя (E-1) с лентой событий (E-2: визит, покупка, бронь; арендатор, проект, дата, сумма). Ключевая трудность — отсутствие общего идентификатора: профили объединяются автоматически только по надёжным ключам (телефон, email, номер карты), спорные пары уходят в очередь на ручное подтверждение, любое объединение обратима, а разъединённые вручную пары повторно не объединяются.

На основе профилей маркетолог УК без кода собирает динамические сегменты (E-3) вида «был в A и B, не был в C» (пять предустановленных шаблонов: «Спящий сосед», «Один магазин», «Риск ухода», «Новичок», «Высокая ценность»). Для каждого гостя система выдаёт до трёх рекомендаций (E-15) по прозрачному скорингу (похожие гости, смежность категорий, этаж/расстояние, свежесть, приоритет арендатора, понижение прямых конкурентов) с текстовым обоснованием и без мест, где гость уже был. Сегмент одним действием выгружается в канал рассылки (CSV и API; SMS/пуш/email) с фильтром по наличию контакта нужного канала, настраиваемым лимитом контактов и опциональной контрольной группой для измерения инкремента. Новое событие обновляет профиль, пересчитывает затронутые сегменты и рекомендации без ручного запуска.

Продукт B2B2C: платит и решает УК (R-2), пользуются маркетолог (R-1) и аналитик (R-4), арендатор (R-3) видит только то, что разрешено грантом УК (по умолчанию — свои агрегаты), посетитель (R-5) — объект данных и получатель рассылки. Технически: Go (handler → service → repository, воркеры + очередь), React SPA (Vite, TypeScript, TanStack Query/Table, React Hook Form, React Router), SQLite на старте с переходом на PostgreSQL без смены модели (3НФ, goose).

Метрики успеха: **главная — первая покупка гостя у нового для него арендатора** (FAQ В-4, A-17); поддерживающие — cross-tenant rate, match rate (≥ 70%), доля оспоренных объединений (< 1%), время сегмент → выгрузка (≤ 5 мин), конверсия рассылки (ориентир ≥ 3%), инкремент визитов против контрольной группы (если она выделена).

## 2. Допущения

Приоритет источников при неясности: `customer-faq.md` → `case.txt` → лучшая практика. **Ответы заказчика имеют приоритет над аналитикой команды**: там, где анализ команды расходится с FAQ, действует FAQ (A-17…A-23 фиксируют эти расхождения). Уточнения для заказчика вынесены в `00-open-questions.md` (Q-n), спорные проектные решения — там же (D-n).

## 3. Границы (вне scope)

Юридические согласия, отписки и реестры отказов, полноценная программа лояльности, собственная отправка SMS/пуш/email, мобильное приложение гостя, интерфейс запроса кампаний для арендатора, платежи и биллинг, real-time стриминг событий.
