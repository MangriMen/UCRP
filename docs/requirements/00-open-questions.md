## 2. Спорные решения

Формат: ID, варианты, выбранный, обоснование, цена отката.

| ID   | Варианты                                                                                                                                                                                                                 | Выбрано                                                                                       | Обоснование                                                                                                                                                                                                                                                | Цена отката                                                                                                          |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| D-1  | (а) автоинкремент INTEGER; (б) UUIDv7/ULID как TEXT, генерируется в приложении                                                                                                                                           | (б)                                                                                           | Одинаково работает в SQLite и PG, нет различий `AUTOINCREMENT`/`SERIAL`; упорядочены по времени; безопасны для публикации в URL                                                                                                                            | Средняя: смена типа ключей затрагивает все FK                                                                        |
| D-2  | (а) `NUMERIC(14,2)`; (б) `BIGINT` в минимальных единицах + `currency`                                                                                                                                                    | (б)                                                                                           | SQLite не имеет точного NUMERIC; целые числа переносимы и точны                                                                                                                                                                                            | Низкая: миграция делением на 100                                                                                     |
| D-3  | (а) JSONB сразу (только PG); (б) TEXT с JSON в обеих СУБД, JSONB отдельной PG-миграцией                                                                                                                                  | (б)                                                                                           | Единый DDL; в общем коде не используются JSON-функции БД; индексы по JSON появятся только в PG                                                                                                                                                             | Низкая: PG-миграция идемпотентна                                                                                     |
| D-4  | (а) событие без ключей отбрасывать; (б) хранить с `guest_id=NULL` и `match_keys`, периодически пытаться привязать; (в) отдельная таблица «карантин»                                                                      | (б)                                                                                           | Нужно для match rate и повторной привязки при появлении ключа; не плодит таблицы                                                                                                                                                                           | Средняя: перенос в карантин-таблицу                                                                                  |
| D-5  | (а) переписывать `guest_id` у событий и идентификаторов при слиянии, помнить `origin_guest_id`; (б) указатель `merged_into_id` без переноса, разрешать цепочки при чтении; (в) отдельная таблица `guest_alias`           | (а)                                                                                           | Запросы сегментов и профиля простые (`guest_id` = канонический), обратимость через `origin_guest_id`; цена — массовый UPDATE при слиянии (обычно сотни строк)                                                                                              | Высокая: смена модели слияния затрагивает identity и все запросы                                                     |
| D-6  | (а) вычислять сегмент на лету; (б) материализовать в `segment_member` по версии                                                                                                                                          | (б)                                                                                           | Требование «размер видно до сохранения» обеспечивает preview (на лету), а сохранённые сегменты нужны для выгрузок, лимитов, кампаний и инкрементального пересчёта; хранятся только текущая и последняя прошлая версия                                      | Низкая: таблица можно убрать, заменив запросом                                                                       |
| D-7  | (а) править правило на месте; (б) неизменяемые версии `segment_version`                                                                                                                                                  | (б)                                                                                           | Воспроизводимость выгрузок и аудит                                                                                                                                                                                                                         | Низкая                                                                                                               |
| D-8  | (а) только каналы Go в памяти; (б) персистентная таблица `job_queue` + воркеры; (в) внешний брокер (Redis, NATS)                                                                                                         | (б) для SQLite/старта, интерфейс `Queue` допускает (в)                                        | Не терять задания при рестарте, нет внешней зависимости на пилоте; одна служебная таблица T-1 добавлена вне списка E-* с обоснованием                                                                                                                      | Низкая: замена реализации `Queue`                                                                                    |
