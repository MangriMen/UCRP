# OpenAPI contract

The source of truth for the REST API: paths, schemas, roles (`x-roles`) and use cases (`x-uc`). Hand-written YAML split by topic; nothing here is generated.

Entry point: `openapi.yaml` (`info`, `servers`, `tags`, `security` and `$ref`s to the files below).

| Path                                                            | Contents                                                                                                                                                          |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `paths/*.yaml`                                                  | Operations grouped by topic (auth, users, reference data, imports, guests, identity, segments, campaigns, exports, analytics, audit, access, invitations, system) |
| `components/schemas/*.yaml`                                     | Models grouped by topic; shared types (`ErrorResponse`, `PageMeta`, `UserRole`) are in `common.yaml`                                                              |
| `components/parameters.yaml`, `responses.yaml`, `security.yaml` | Shared parameters, error responses, `bearerAuth` and `cookieAuth`                                                                                                 |

## Commands

```sh
bun run --cwd packages/api-docs lint          # redocly lint
bun run --cwd packages/api-docs build         # bundle to dist/openapi.yaml for Swagger UI
bun run --cwd packages/api-docs bundle:json   # bundle to dist/openapi.json (used by e2e tests)
```

## Rules

1. The spec is the source of truth: change it first, then the code, then `docs/design/endpoint-registry.md`.
2. Put a schema in the matching topic file and reference it from the operation.
3. Cross-file references are relative with a JSON Pointer: `../components/schemas/common.yaml#/PageMeta`.
4. Keep files under about 300 lines; split a topic when it grows.
5. Run lint after every change; frontend types in `packages/api-types` are generated by the build and never committed.
