# Pull request description

## Rules

- Title: Conventional Commits, e.g. `feat(api): add guest import endpoint`.
- Body: two to five lines or a few bullets on what changes and why. No file-by-file listing; the diff shows that.
- No template sections, headings, checklists, "How to verify" or "Related" blocks. Add a line only when it carries real information: a breaking change, a manual step after merge, something deliberately left out.
- Mention a task or issue only if there is one, as plain text (`Closes #12`).
- Do not claim checks you did not run; say what was not run.
- No attribution lines or generated-by footers.
